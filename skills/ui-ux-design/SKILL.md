# UI and UX design

**When activated:** Apply this only if the actual task matches the description. First inspect available evidence and select relevant references; do not infer project details from the skill name.

## Workflow
1. Inspect product purpose, user goals, content priorities, existing components and visual identity before sketching layouts.
2. Map information hierarchy, navigation and primary actions; design low-fidelity structure before detailed aesthetics.
3. Choose intentional typography, layout rhythm, whitespace, contrast and imagery appropriate to audience and brand.
4. Design all interaction states: hover, focus, active, loading, empty, validation, permissions and failure; avoid inaccessible visual-only cues.
5. Compare alternatives against real tasks and preserve working behavior; review desktop, mobile, keyboard and zoom scenarios.

## Deliverable
Screen plan, interaction/state inventory and design rationale with review checklist.

## Quality gate
Report what was **observed**, what is **proposed**, which checks **passed/failed/were not run**, and any remaining risks. Use tools only when available and authorised. For destructive, financial, production or customer-data changes, require explicit approval. Never claim a test, screenshot, design file, deployment or tool action exists without evidence.
