# Native and cross-platform mobile engineering

**When activated:** Apply this only if the actual task matches the description. First inspect available evidence and select relevant references; do not infer project details from the skill name.

## Workflow
1. Identify platform targets, framework versions, navigation, permissions, safe areas and supported device ranges.
2. Plan app lifecycle, offline behavior, secure storage, background limitations and runtime/network errors.
3. Use platform-native patterns where possible; verify performance of lists, animation, images and accessibility.
4. Handle privacy permissions and app-store policy changes using current official documentation.
5. Test realistic devices, lifecycle interruptions, updates, denied permissions and accessibility input modes.

## Deliverable
Platform matrix, architecture and test plan with policy caveats.

## Quality gate
Report what was **observed**, what is **proposed**, which checks **passed/failed/were not run**, and any remaining risks. Use tools only when available and authorised. For destructive, financial, production or customer-data changes, require explicit approval. Never claim a test, screenshot, design file, deployment or tool action exists without evidence.
