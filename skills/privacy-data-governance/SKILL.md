# Privacy and data governance

**When activated:** Apply this only if the actual task matches the description. First inspect available evidence and select relevant references; do not infer project details from the skill name.

## Workflow
1. Classify data and map collection, storage, transfers, processors, access and deletion flows.
2. Apply data minimization and purpose limitation; define retention, user access and deletion policy per applicable requirements.
3. Restrict access by role and tenant, encrypt appropriately and redact logs, analytics and support exports.
4. Plan consent and permission changes, breach response, backup lifecycle and third-party agreements for the jurisdiction.
5. Document residual risks and recommend specialist legal review instead of asserting compliance certifications.

## Deliverable
Data inventory, retention matrix, access controls and privacy risk register.

## Quality gate
Report what was **observed**, what is **proposed**, which checks **passed/failed/were not run**, and any remaining risks. Use tools only when available and authorised. For destructive, financial, production or customer-data changes, require explicit approval. Never claim a test, screenshot, design file, deployment or tool action exists without evidence.
