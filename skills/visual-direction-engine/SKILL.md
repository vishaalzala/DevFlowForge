# Visual direction engine — distinctive, evidence-based concepts

Start with `ui-ux-design`, `design-systems-tokens`, and the real product information. Read `../../references/design-intelligence-quality.md`. This workflow is not a licensed theme library or an AI image generator; it makes choices explicit and gives a developer an implementable brief.

1. Inspect product purpose, primary user job, audience, existing visual identity, approved references, content hierarchy, licensed imagery, typography choices and framework restrictions. An existing locked design system wins unless the user requests changes.
2. Produce **three materially different directions** (unless the user requested only one). Vary composition, visual rhythm, information architecture, type contrast and interaction model, not merely accent colours. For each, state a memorable concept, why it suits the product, its content hierarchy, hero or first-screen treatment, responsive interpretation, accessibility and component implications.
3. Distinguish **facts** (provided assets, metrics, testimonials, copy, photos) from **proposed placeholders**. Do not manufacture social proof or import unlicensed images; cite or log allowed asset sources and attribution requirements.
4. Use design tokens for palette, spacing, typography, radii and motion, and specify all content states including loading, empty, long, invalid, error and keyboard focus. Keep visual choices consistent within each concept.
5. Explain audience trade-offs and select a candidate only after comparing usability, originality, implementation costs, brand fit and the user's constraints. Avoid a mandatory list of forbidden colours, gradients or card shapes: stylistic heuristics are reviewable, not universal laws.
6. Prototype the chosen direction before implementing. For existing pages, ask whether the task is **polish**, **restyle** or **redesign**; require explicit scope before replacing layouts or working components. Pair with `design-preservation-verification` before a redesign is approved for release.

**Output:** Three distinct design briefs, rationales, token suggestions, responsive/layout states, real asset inventory, an explicit recommendation and verification criteria. If a helper script suggests concepts, it is illustrative, not a substitute for a human design decision.
