# Dashboard and data visualization design

**When activated:** Apply this only if the actual task matches the description. First inspect available evidence and select relevant references; do not infer project details from the skill name.

## Workflow
1. Map user decisions to metrics and data sources; avoid charts that do not support a concrete decision.
2. Specify definitions, units, freshness, timezone, filters, empty states, loading and access scopes for every metric.
3. Choose visual encoding matching data type; include axis labels, legends, comparison context and accessible alternatives.
4. Design responsive tables, long values, pagination, sorting, sticky regions and drill-downs without hiding key information.
5. Test visual clarity with real sample data, outliers, missing values and permissions across user roles.

## Deliverable
Dashboard wireframe, metric dictionary, chart choices and usability validation.

## Quality gate
Report what was **observed**, what is **proposed**, which checks **passed/failed/were not run**, and any remaining risks. Use tools only when available and authorised. For destructive, financial, production or customer-data changes, require explicit approval. Never claim a test, screenshot, design file, deployment or tool action exists without evidence.
