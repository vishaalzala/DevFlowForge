# User research and journey mapping

**When activated:** Apply this only if the actual task matches the description. First inspect available evidence and select relevant references; do not infer project details from the skill name.

## Workflow
1. Identify audience, use context, accessibility needs, major jobs to be done and channels; avoid stereotypes or fabricated personas.
2. Build task scenarios and journey stages with observed touchpoints, expectations, friction and possible moments of failure.
3. Combine qualitative findings with funnel or service data if available, labeling sample sizes, limitations and inferred patterns.
4. Prioritize high-friction moments and propose testable improvements to user paths, messages and recovery states.
5. Validate the proposal with representative users and record dissenting results before handing off to design.

## Deliverable
Journey map, evidence table, prioritized usability questions and validation plan.

## Quality gate
Report what was **observed**, what is **proposed**, which checks **passed/failed/were not run**, and any remaining risks. Use tools only when available and authorised. For destructive, financial, production or customer-data changes, require explicit approval. Never claim a test, screenshot, design file, deployment or tool action exists without evidence.
