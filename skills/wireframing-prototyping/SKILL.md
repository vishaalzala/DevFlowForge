# Wireframing and interaction prototyping

**When activated:** Apply this only if the actual task matches the description. First inspect available evidence and select relevant references; do not infer project details from the skill name.

## Workflow
1. Define the user task, success state and decision being tested; sketch the minimal flow including alternate paths.
2. Create clear low-fidelity wireframes before high-fidelity decoration; use realistic labels and content lengths.
3. Document click targets, navigation transitions, form validation, keyboard order and accessible interaction expectations.
4. Prototype only the behavior needed to answer the design question; mark nonfunctional placeholders explicitly.
5. Run task-based usability checks and revise based on observed confusion and completion rates.

## Deliverable
Annotated flow, prototype scope, usability test script and findings.

## Quality gate
Report what was **observed**, what is **proposed**, which checks **passed/failed/were not run**, and any remaining risks. Use tools only when available and authorised. For destructive, financial, production or customer-data changes, require explicit approval. Never claim a test, screenshot, design file, deployment or tool action exists without evidence.
