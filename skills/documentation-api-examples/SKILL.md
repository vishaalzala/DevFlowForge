# Developer documentation and examples

**When activated:** Apply this only if the actual task matches the description. First inspect available evidence and select relevant references; do not infer project details from the skill name.

## Workflow
1. Identify target reader, supported platforms and exact version prerequisites before drafting instructions.
2. Organize quickstart, reference, examples, troubleshooting and limitations for task-oriented navigation.
3. Make commands copyable and safe; verify paths, package names, expected outputs, credentials handling and links.
4. Keep examples aligned with actual API behavior and provide failure cases rather than happy path only.
5. Run a fresh-start installation or docs test where possible and label anything unverified.

## Deliverable
Task-tested documentation, examples and known-issues list.

## Quality gate
Report what was **observed**, what is **proposed**, which checks **passed/failed/were not run**, and any remaining risks. Use tools only when available and authorised. For destructive, financial, production or customer-data changes, require explicit approval. Never claim a test, screenshot, design file, deployment or tool action exists without evidence.
