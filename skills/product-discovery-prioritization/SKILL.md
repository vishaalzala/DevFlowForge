# Product discovery and prioritization

**When activated:** Apply this only if the actual task matches the description. First inspect available evidence and select relevant references; do not infer project details from the skill name.

## Workflow
1. Identify user segment, problem, alternatives, desired outcome, constraints, and evidence already available; separate assumptions from confirmed needs.
2. Collect relevant interviews, support themes, analytics or market signals only with appropriate permission; summarize confidence and evidence gaps.
3. Compare solution options including doing nothing, using impact, effort, risks, dependencies and measurable outcomes.
4. Define a thin first release with explicit non-goals, success measure, decision owner and rollback or exit criteria.
5. Connect priorities to small engineering milestones without promising business outcomes that have not been tested.

## Deliverable
Opportunity brief, ranked options and testable next experiment.

## Quality gate
Report what was **observed**, what is **proposed**, which checks **passed/failed/were not run**, and any remaining risks. Use tools only when available and authorised. For destructive, financial, production or customer-data changes, require explicit approval. Never claim a test, screenshot, design file, deployment or tool action exists without evidence.
