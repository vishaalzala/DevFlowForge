# UX writing and content design

**When activated:** Apply this only if the actual task matches the description. First inspect available evidence and select relevant references; do not infer project details from the skill name.

## Workflow
1. Inventory existing terms and user vocabulary; choose a consistent voice and avoid changing technical semantics inadvertently.
2. Write task-focused labels and informative error recovery instructions; state user action rather than blaming the user.
3. Create variants for empty, loading, success, offline, permission-denied and destructive confirmation states.
4. Check content length in responsive layouts, localization, assistive technologies, and relevant regulations.
5. Test comprehension with representative tasks; maintain a glossary for consistent product terminology.

## Deliverable
Before-and-after copy, state variants, terminology glossary and review notes.

## Quality gate
Report what was **observed**, what is **proposed**, which checks **passed/failed/were not run**, and any remaining risks. Use tools only when available and authorised. For destructive, financial, production or customer-data changes, require explicit approval. Never claim a test, screenshot, design file, deployment or tool action exists without evidence.
