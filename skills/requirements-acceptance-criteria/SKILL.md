# Requirements and acceptance criteria

**Goal:** Establish what success means before implementation without inventing requirements.

1. Separate user goals, non-goals, constraints, stakeholders, dependencies and existing behavior. Ask for missing essentials only when the work cannot reasonably proceed.
2. Translate requirements into observable acceptance cases using Given / When / Then or equivalent; include normal paths, boundary conditions, error states, permissions and accessibility.
3. Inspect existing code, tests and documentation before proposing new features; avoid duplicating functionality.
4. Prioritize requirements by impact, risk and dependencies, recording uncertainties and explicit assumptions.
5. Identify compatibility constraints, operational impacts, rollout and rollback needs for sensitive changes.
6. Produce a compact scope statement, acceptance checklist, test mapping and definition of done. Mark unverified assumptions clearly.

**Evidence:** Link each acceptance criterion to a proposed or executed test; state which remain unverified.
